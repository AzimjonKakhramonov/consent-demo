# Consent check-in demo

Демо на Node.js, Express и обычном JavaScript для локального запуска или Render. Страница собирает фото и геопозицию **только с явного согласия посетителя**. Предназначено для добровольной проверки на себе, не для проверки личности или банковского liveness.

## Запуск

Нужен Node.js 22 или новее. В терминале из этой папки:

```powershell
npm i
Copy-Item .env.example .env
# Откройте .env в редакторе и заполните поля локально.
npm start
```

Если `.env` уже существует, не перезаписывайте его копированием. В macOS/Linux вместо Copy-Item используйте `cp .env.example .env`.

Откройте http://localhost:3000 (либо PORT из `.env`). При локальном запуске сервер слушает только `127.0.0.1`. Отдельной сборки нет. Для Render — отдельный режим ниже.

- `TELEGRAM_BOT_TOKEN`: токен собственного бота из BotFather.
- `TELEGRAM_CHAT_ID`: ID своего личного чата с этим ботом. Владелец должен сам начать диалог с ботом. Если ID неизвестен, его можно получить локально из `message.chat.id` ответа Bot API `getUpdates` после собственного сообщения; не вставляйте токен в адресную строку браузера, логи или переписку. У ботов с webhook этот метод недоступен; настройки существующего бота ради демо не меняйте.
- `PORT`: необязательный порт, по умолчанию `3000`.

При локальном запуске секреты читаются только из `.env` рядом с `server.js`, не из окружения другого бота. `.env` и `.env.*` исключены из Git, кроме пустого `.env.example`. Без токена/ID сервер и предпросмотр работают, но кнопка отправки вернёт понятную ошибку без обращения к Telegram. После изменения `.env` перезапустите сервер. Остановка: Ctrl+C.

## Публикация в Render

1. Разместите исходники в своём GitHub-репозитории (можно приватном). Не загружайте `.env`, `node_modules`, фотографии, координаты или секреты.
2. В Render выберите **New → Blueprint**, подключите репозиторий и примените `render.yaml`. Он задаёт Node 22, Free Web Service, `npm ci --omit=dev`, `npm start` и `/healthz`. Создание аккаунта и подключение GitHub выполняет владелец.
3. После успешного деплоя откройте HTTPS-ссылку, которую покажет Render. Конкретный адрес назначается при создании сервиса; заранее существующая ссылка не предполагается.
4. Без дополнительных настроек работают страница, камера, геолокация и предпросмотр; отправка отключена. Для отправки владелец задаёт `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в **Environment** этого сервиса и применяет изменения с перезапуском. Значения не добавляются в Git или `render.yaml`.
5. Проверьте на своём устройстве согласие, разрешения, фото, предпросмотр и отдельную отправку. Настоящая отправка в Telegram не входит в автоматические тесты.

Если создаёте **New → Web Service** вручную: Runtime **Node**, Build Command `npm ci --omit=dev`, Start Command `npm start`, Health Check Path `/healthz`, план **Free**, переменная `NODE_VERSION=22`.

Render сам задаёт `RENDER=true`, `PORT` и `RENDER_EXTERNAL_URL`. Только в этом режиме сервер слушает `0.0.0.0` и читает настройки из окружения сервиса. Разрешён точный HTTPS-origin из `RENDER_EXTERNAL_URL`; поддомены и произвольные Origin/Host не принимаются. Пользовательские домены пока не поддержаны. Health check доступен без проверки Host и возвращает только `{ "ok": true }`.

Сервис доступен всем, у кого есть ссылка. При нажатии отправки фото и координаты проходят через Render в Telegram. Приложение не сохраняет их на диске и не пишет в логи; хостинг может вести собственные технические журналы. В публичном режиме действует общий лимит 10 попыток отправки в минуту на процесс, без хранения IP. Это ограничение для демо, не авторизация: любой посетитель может израсходовать общий лимит; рестарт сбрасывает его.

Free-сервис Render засыпает после 15 минут без входящих запросов; первый запрос после сна может открываться около минуты. Автоматический деплой здесь ещё не означает проверку реальной камеры или доставки.

Документация Render: [Web Services](https://render.com/docs/web-services), [Blueprint](https://render.com/docs/blueprint-spec), [переменные окружения](https://render.com/docs/environment-variables), [Free](https://render.com/docs/free).

## Как работает согласие

1. При загрузке камера и геолокация не запрашиваются. Ничего не отправляется.
2. Посетитель читает описание и нажимает «Включить камеру и определить геопозицию». Отдельной галочки нет: согласие на предпросмотр выражается этой кнопкой. Используются штатные `getUserMedia` и `getCurrentPosition`. Сохранённое разрешение браузер может применить без повторного запроса; явная кнопка страницы всё равно обязательна.
3. После получения координат посетитель нажимает «Сделать фото». Камера сразу выключается. На странице показываются фото, широта, долгота и точность.
4. Только кнопка «Отправить фото и координаты в Telegram» делает POST на сервер приложения. Он вызывает `sendPhoto`: фото и координаты в подписи одного сообщения уходят в чат владельца, указанный в `.env` локально или в окружении Render. Получателя нельзя изменить из браузера.
5. Отмена очищает черновик. Скрытие вкладки очищает черновик и выключает камеру; закрытие страницы тоже выключает камеру. Предпросмотр камеры ограничен двумя минутами. Во время отправки очистка недоступна: уже переданный запрос отменить надёжно нельзя.

Фото и координаты до отправки находятся только в памяти вкладки; сервер не записывает их на диск и не логирует. Нет аналитики, сторонних шрифтов, карт, localStorage или фонового отслеживания. После отправки сообщение хранится в Telegram: очистка страницы его не удаляет.

Отказ в разрешении или ошибка геолокации не приводят к отправке. Если подтверждение Telegram не пришло, проверьте чат перед повторным нажатием: сообщение могло дойти. Автоматических повторов нет. Поле `consent` API — проверка структуры запроса, а не доказательство юридического согласия или защита от специально написанного клиента. Это демо без авторизации; не используйте его как готовый сервис проверки личности.

## Проверки без реальных отправок

```powershell
node --check server.js
node --check public/app.js
node --test test/server.test.js
```

Серверные тесты подменяют Telegram transport в памяти; настоящие API-запросы не выполняются, `.env` не читается. Можно открыть страницу без `.env`: до согласия и до отдельной кнопки отправки POST-запросов быть не должно. Не вводите реальные секреты в тесты.

Документация API: [Telegram sendPhoto](https://core.telegram.org/bots/api#sendphoto), [камера](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [геолокация](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition).
